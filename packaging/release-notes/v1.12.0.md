jekyll-vitepress-theme 1.12.0 publishes every version of your docs with one command: the latest release at `/`, your default branch at `/next/`, and older major versions you keep, each with a version selector, a banner on unreleased and older docs, and titles that name the version.

```sh
bundle update jekyll-vitepress-theme
```

![The /next/ docs with the version banner above the navigation and the version selector open](https://github.com/crmne/jekyll-vitepress-theme/releases/download/v1.12.0/version-banner.png)

## New

* **Versioned docs from release tags.** Add `versions: { next: true }` under `jekyll_vitepress` in `_config.yml`, and `bundle exec jekyll-vitepress build` builds the newest release tag at `/` and the checkout at `/next/`. List older major versions under `keep` to keep them online, such as the newest 1.x at `/v1/`, and `redirect_missing` sends URLs that only exist there into it. Every release is built from its own tag with your current docs `Gemfile`, so theme fixes reach old versions too. Until the first release tag exists, it builds the checkout once. By @crmne
* **Each version says which one it is.** The version selector lists every version plus the links in `_data/versions.yml`. `/next/` and older versions show a banner linking to the stable docs, and their page titles and link previews name the version, such as "Chat | MyGem Next". Canonical URLs, sitemaps, search, and `llms.txt` stay inside each version, and `robots.txt` lists every version's sitemap. By @crmne
* **`jekyll-vitepress serve` previews every version.** It builds the site, serves it, and rebuilds the checkout's version as you edit. By @crmne
* **Build hooks.** `jekyll_vitepress.build` runs commands before and after each version's build and once the site is assembled, for API references, generated pages, or files copied into the site. By @crmne
* **A reusable GitHub Pages workflow.** `uses: crmne/jekyll-vitepress-theme/.github/workflows/publish-docs.yml@v1` builds with `jekyll-vitepress build`, deploys to GitHub Pages, and submits changed pages to IndexNow when the repository has the script. See [Deployment](https://jekyll-vitepress.dev/deployment/) for the whole setup. By @crmne

## Fixed

* **Pages outside collections no longer get a bogus `dir` attribute.** The home page and other standalone pages rendered `<html dir="/">`, because Jekyll's `page.dir` is a URL directory, and ignored a site-wide `dir: rtl`. Only `rtl`, `ltr`, and `auto` are used now. By @crmne

## Changed

* **The `gh-pages` publishing scripts are gone from the repository.** `scripts/version_manifest.rb` and `scripts/publish_gh_pages.sh` were never part of the gem; `jekyll-vitepress build` and the reusable workflow replace them. By @crmne
